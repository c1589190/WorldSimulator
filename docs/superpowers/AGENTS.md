# docs/superpowers/AGENTS.md —— 设计目录规则

> **本文件属于项目设计目录的维护索引，不是设计正文。**
> 设计权威顺序与文档系统总规则见 `../AGENTS.md`；根路由见 `../../AGENTS.md`；当前状态见 `../agents/STATUS.md`。

## 目录职责

| 路径 | 放什么 | 不放什么 |
|---|---|---|
| `specs/**` | 用户设计原稿、专题设计、契约、状态机、工具面、领域不变量 | 当前测试数字、一次性证据、维护流程 |
| `reports/**` | 调查、邻仓侦察、可行性分析、独立复核 | 当作当前设计正本使用 |
| `plans/**` | 进行中的实现计划、任务拆分、验收判据 | 反复更新的实时状态 |
| `status/**` | 某时点的状态快照、交接、证据摘要 | 当前唯一状态入口 |
| `DESIGN_RULINGS.md` | 设计裁定索引：用户原话出处、专题落点、被取代关系 | 维护裁定 |

## 命名与状态头

- 文件名：`YYYY-MM-DD-<主题>.md`。
- 每篇设计/报告必须有状态头，至少写：
  - `> **状态**：有效 | 待用户评审 | 历史 | 调研输入`
  - `> **日期**：YYYY-MM-DD`
  - `> **本文性质**：用户设计目标 / 专题设计 / 工程建议 / 调查证据`
  - 如取代旧文：`> **本文取代**：<路径>（日期）`
  - 如被取代：`> **状态**：历史（日期）· **取代者**：<路径> · **勿据此开工**`
- 引用用户原话必须逐字，并给日期；不得把工程推导写成用户裁定。
- 现状事实要带 `file:line`；没有跑过的验证写 `NOT_RUN` / `未验证` / `BLOCKED`。

## 设计正文的最低结构

1. 用户目标 / 原话出处
2. 范围与非目标
3. 数据所有权与模块边界
4. 核心实体 / 地址 / 状态机
5. 工具面 / API / 载荷
6. 不变量与失败语义
7. 导出与兼容
8. 验收判据
9. 未定项
10. 参考与证据

## 设计裁定索引

维护 `DESIGN_RULINGS.md` 时：

- 一行一条裁定，写 `编号 / 日期 / 来源（用户原话或专题） / 主正本 / 状态`。
- 用户明确目标与工程建议分开；工程建议不得标成“用户裁定”。
- 旧条目被取代时保留并加指向，不静默删除。
