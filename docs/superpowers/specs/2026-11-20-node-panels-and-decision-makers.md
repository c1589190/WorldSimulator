## 1. 目标与开工基线

在选定的时间线节点点击地块，右栏显示地块资料、归属和实际控制，并能打开同节点的左侧国家面板。国家和单个已部署军事单位均可绑定独立决策人，并在各自面板查看该回合的决策。

## 2. 界面与数据所有权

- 右栏保持地块和区域选中。将省查询已有的归属、控制映射为带名称、同节点国家地址和证据的关联项。同国可合并展示两个标签。归属与控制不同则分别显示，两种未知原样展示。点击国家只切换左栏内容和实体焦点，地图保持原位置和右栏省情。
- 左栏沿用军队面板的布局，按所选对象切换国家档案、单位信息或叠牌名单。国家先显示名称、首都、政体、政府、动员、归属与实控摘要，有数据时展示条约、人力和本期运力。单位沿用现有部署、实编和编制图。国家与单位都可从栏头打开决策窗口。地块选择与左栏实体焦点独立，只有焦点为单个部队时绘制行军箭头。
- 右栏分步增加人口、铁路与补给中心。人口带日期、口径、证据状态和来源。列表优先使用日期不晚于该节点、同口径下最近一条有来源的记录，较早记录标明原日期，统计口径可切换。每条铁路与枢纽使用现有 ID；跨河属于相邻边，按具体方向及证据展开。数值为空时显示未知。史料缺项沿用核对流程逐步补录。
- 地图、国家、ORBAT、INFO 和回合继续各自持有领域数据。查看器只读取面板所需的同节点投影。首版省情引用现有地理和人口数据，省级产业与行政专题沿后续推演需求制定。

## 3. 决策人、主管对象与授权

把现有“国家 ID 就是参与身份”推广到稳定的 `decisionMakerId`。回合开放时冻结每个决策人的展示名、主管对象和授权。主管对象记录类型和稳定实体 ID，首版支持 `country` 和 `orbat/unit`。国家政府与同国某个单位的指挥者各有独立身份和回执。一个宿主 Agent 可以承接多个身份，每个会话由可信宿主选择一个身份。

- 国家和单位地址沿用 `<node>/country/<id>` 和 `<node>/orbat/unit/<id>`。决策人可从面板导航到同节点的主管对象。记录保存稳定 ID，读取时解析为节点地址，旧节点用当时的主管对象和显示名。
- `openTurn.brief.participants` 用决策人 ID 为键，每项保存 `displayName`、`subject {kind,id}`、`readablePaths` 和 `proposalTargets`。新 INFO 通过 `decisionAudience` 明确收件人。
- `readablePaths` 和可提交的目标范围分别由 GM 配置。授予读权限不会扩大可提交目标。决策工具提交正文、理由及目标，一条收件按“回合基点、回合 ID、决策人 ID”唯一。所属国家与指挥隶属提供上下文，授权由 GM 明确发放。单位决策人只收到明确发给自己的 INFO。
- 国家提案与单位提案在同一回合可以并存。GM 统一选择和裁决，并用现有命令保存。回合总说明和逐条裁定遵循 §9。
- 决策人不会因提交而执行行军、控制或库存变更。落库仍通过 `Command → ChangeSet → TimelineNode`。历史决策绑定发布时的身份与主体，单位转隶、改名或消失后仍能回看原决策。

## 4. 回合在节点上的含义

回合按所选正式分支的发布顺序定位。当前节点有已开放回合时，面板显示该回合的参与人和可用收件。已结算节点可回看归档输入及裁决，并标记“最近结算回合”。未分配、待提交、已收件和已裁决分别用明确状态表示。

处在正式分支的开放基点时，可按需读 GM 收件，显示收件节点和读取得到的状态。回看历史节点时使用该时刻正式状态及已归档结果。收件分支是独立记录，可以从回合细节打开。页面不会将后到收件写回旧节点或把其他分支的决策当作当前回合。节点或选中对象切换时，按稳定 ID 重新解析并取消过期的面板请求。

## 5. 接口与交付顺序

1. **省 → 国家。** 给现有 `/api/province` 与 `/api/pick` 的关系字段加同节点链接。让国家搜索和军队面板的国家链接走同一个左栏入口。复用 `/api/entity` 读取国家档案，右栏保留省情。
2. **国家与单位决策人。** 以新可选载荷保存参与身份及 INFO 受众，继续复用 AgentLib、GM 草稿、收件分支和现有三个决策工具。新会话用决策人 ID 绑定。旧版国家回合、`--decision-country` 启动和已有收件分支按原口径读取。
3. **两个面板接入当前回合。** 在应用层按节点、对象和回合组装同一份只读投影，浏览器按需取数。返回对象地址、节点及 hash、回合基点、决策人、收件和可用裁决。沿用本地 GM 查看器的 GET 边界。决策人入口通过同一权限筛选层走 MCP。浏览器不通过公开参数选择决策人身份。
4. **省情补齐。** 优先接人口查询和普查日期选项，再接已有铁路、枢纽和相邻跨河条件。首版以一个有人口记录的演练省和一个未知省验证，正式 1936 人口使用史料来源录入。沿用同一导入工具、证据状态和节点回放。

## 6. 兼容与失败语义

新增载荷可选。旧状态保留原序列化字节、节点哈希、国别 INFO 和收件路径，读取投影补出国家参与者。世界导出带新增数据与对应增量。地址不属于当前节点、未授权读或提交、身份不存在、过期响应、资料缺项各有可解释结果。不会把某次收件失败、旧记录缺失或未知人口显示为已提交或零值。

面板请求只查当前对象，人口和设施查询按需读取。旧地图及瓦片缓存路径沿用当前行为。验收用同一 1936 分支切换节点，测量面板加载和地图切换时延。

## 7. 验收与待定项

- 用一个已校对省打开所属国家并保留右侧轮廓，用占领演练省点击两种国家关系，再从国家首都或单位链接返回到原节点。
- 同一回合给波兰政府与两个同级单位绑定不同身份，各执一次授权简报并提交。确认兄弟单位和国别之间的越权读取或提交被拒，再在国家、各单位分别回看各自记录。旧德波国家回合完整校验。
- 在开放节点、结算节点、前一历史节点及叉分支切换，核对同节点 hash、当时身份、收件时间和归档裁决。快切时核对过期响应未覆盖当前对象。
- 人口校验确认值、估计、不同日期或口径及未知状态。验证铁路/枢纽证据、相邻跨河方向和海陆差异。人口与经济资料的正式扩充延用项目史料工作流。
- 首版把独立决策授权落在可寻址的部署单位。后续如果需要将编制树内的未部署下属也作为独立授权实体，需要另定授权范围和显示入口。面向决策人自身的浏览器视图待后续扩展。

## 8. 实现入口

可信宿主在世界工作目录下启动 `mcp --decision-turn <node>/turn/<id> --decision-maker <id>`，同一世界的 stdio 会话依次运行。已有国别回合可继续用 `--decision-country`。GM 浏览器用携带 `node`、`hash`、`address` 的 GET 请求读取 `/api/decisions`、`/api/province/population` 和 `/api/province/logistics`。国家归属与控制地址随省查询返回。

实测步骤、回执和仍待补录的开局资料见[当前状态](../../agents/STATUS.md#2026-11-20-节点面板与通用决策人验收)。

## 9. 决策原文与 GM 裁定

实体的「查看决策」位于左栏栏头，在浏览器内弹窗逐一展示身份、提案原文、理由、目标、收件与该提案的 GM 批示。时间线上方的「本回合裁定」独立打开全部裁定，含与具体提案无关的 GM 裁定和回合总说明。切换实体或节点后重新打开窗口即可查看对应记录。裁定列表可进入相关实体的决策原文，即使后来该实体不再可查询。

`resolveTurn` 保留总说明 `resolution`，新增可选的有序 `rulings`。每项有回合内唯一的 `id`、标题 `title` 和批示正文 `text`。针对已收件提案的记录另有 `decisionMakerId` 和 `disposition`（`accepted`、`modified`、`rejected`、`deferred`）；不针对提案的裁定省略这两个字段。身份和提案关联来自冻结的参与者和已归档收件。同一身份允许多项裁定。未填写逐条裁定显示「无逐条批示记录」，旧数据仍保留原总说明和 hash。

裁定随 `resolveTurn` 及同批领域命令经过草稿提交。世界状态变更由同批的领域命令表达。查看器按节点和 hash 经 `/api/turn/rulings` 读取回合裁定，经 `/api/decisions` 读取提案原文与对应批示。浏览器以纯文本保留原文段落。

ProjectMosire 的 Agent 执行、工作区和 Docs 由可信宿主装配。WorldSimulator 当前只提供绑定回合和身份的工具。接入完整宿主时，身份和会话使用独立工作区，GM 下发材料使用明确授权，共享史料只读，研究笔记写入本身份的 Docs；最终提交和裁定仍以世界节点中的记录为准。
