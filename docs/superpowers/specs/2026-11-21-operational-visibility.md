## 节点数据

地图设施使用 `map/feature/<id>`，类型为港口或资源点，绑定陆省。港口可指定相邻海省、等级与运营状态。资源点记品类与有据产量。空值表示未知。GM 通过 `putMapFeature` 更新。阶段一使用已有单位移动和陆地邻接完成闭环，铁路和海运的运力及在途规则另定。

参谋机关使用 `orbat/command/<id>`，类型为总参谋部或集团军参谋部。一个国家至多有一个总参，集团军参谋部可挂在同国总参下，单位只能直属一个机关。机关可引用现有机关库存。组织变更通过 `putHeadquarters`，回合可将身份绑定到机关。

INFO 保存国家文档 `info/document/<id>` 与情报标记 `info/contact/<id>`。文档区分核心和对外，外部文档可公开或按国家列表共享。核心文档限 GM 和其国家决策席。发布时冻结正文；外部 Docs 元数据可随正文记录。标记只含疑似单位、陆省、观测时间、说明与证据，发布者和接收决定人各自保存。撤回从当前节点移除记录，历史仍可见。

## 会话

新回合在 brief 启用 `scoped`。决定人由服务端绑定；公共地图设施在 scoped 查询中可见；国家仅投影公开身份与授权文档。真实单位需本人、指挥关系或精确授权。完整 ORBAT 与关系列表仍按明确授权。GM 查看器维持完整视角。启用决策查看器时仅提供同一身份投影。

决策人可提交结构化陆路调动意图与情报操作。单位及参谋机关只能提交其指挥范围内单位的意图，目的地及途经省采用同节点地址。写情报使用身份和回合中 GM 明确配置的接收者许可，不能改写 GM 或其他身份的条目。回合收件可含新建、更新与撤回。在情报阶段专用回合结算发布后，参与者在正式决策回合能读到相应投递。GM 的直接情报命令在发布节点生效，发布者固定为 GM。已批准的调动意图由 GM 核实路线并按既有 `startMarch` 与事件时钟推进。

新增字段省略空值，保持已存在的节点哈希。验收包括非接收者查询、旧回合读取、节点回放、设施查址与地图展示，以及一条 GM 批准并执行的陆路调动。

## 部队观察视角与情报兵牌

2026-11-21 用户原话

> 你说有没有一种可能，那就是情报单位同样应该以军事单位的形式显示，钢4也是这样的；具体就是，选中一个单位的时候，虚化、半透明化其所有视野内不可见的实际单位，只以单位形式显示其掌握的情报单位，而不是以一个抽象的点，明白我的意思吗？

GM 查看器单选部署单位时，使用该节点最近回合中绑定到该单位的可见面身份，沿用决策 MCP 的读取判定。多个席位可切换，初始使用按身份 ID 排序的首席位。缺少绑定时只确认本单位。明确可见的部署保持正常，其他部署显示灰色半透明底影。选中叠牌、关闭单位选择时恢复全图。沿时间线保留同一单位的选中时，按新节点重新查询。此观察模式按节点授权显示，地理距离、单位阵营和情报正文均不自动授予真值访问。

情报沿用 `info/contact/<id>` 的观测地点和证据，采用带虚线边框与问号的兵牌，点开读取原始报告。单选单位时只呈现其席位获准读取的情报。全局 GM 图显示所有报告。情报可缩放聚合，计数注明报告数量。灰色部署不计入可见兵牌叠数。可信 GM 查看器通过 `/api/unit-perspective` 按 `node`、`hash`、`address` 读取各席位允许的部署和标记地址。独立决策视角采用相同画法，并继续仅传输已授权兵牌及报告。
