# 行军与交战的地图条件

> **状态**：有效（首个实施切片）
> **日期**：2026-11-20
> **本文性质**：专题设计
> **依据**：[调查与候选方案](../reports/2026-11-20-event-timeline-and-world-domains.md#2-地形跨河铁路和补给) · [战斗与行军规则](2026-11-20-battle-and-march-conditions.md)

军队从同一节点读取地形、过河证据、铁路及补给。对两个陆省之间的普通邻接，读取出发和进入地形，并从共享边界判断河线与边的关系。单个省中的河流只在该河线接近共享边时影响候选。查询返回 `candidate`、`none-in-reference` 或 `unknown`，同时附参考来源、原始图源 hash、与共享边的位置关系及候选宽度级。河线相交或靠近是外部图源证据，经过 GM 核对后可保存确认结论。

`setRiverCrossing` 以同节点的 `fromAddress`、`toAddress`、`crossesRiver` 和 `evidence` 设置该邻接的跨河事实。布尔值分别表示确认跨河和确认不跨河。两者都设为 `null` 时清除确认。确认与当时的省形关联，查询和重建邻接时只采用匹配省形的确认。候选和确认可在行军与交战条件中追溯。首版报告这些条件，沿用已有行军时长参数。

铁路按线路的连续省对匹配，返回线路 ID、等级及运行记录。`putRailway` 的可选 `operation` 可保存 `open`、`closed` 或 `unknown`、有来源的日运能和证据。缺少运行记录的线路仍参与既有的国内铁路连通估算。确认停用的线路从连通图排除。运能字段供查询，补给仍按连通性和现行地形系数计算。

`world_movement_estimate` 的每段和新发出的行军记录带 `edge` 条件。旧路线可照原样重放。只读工具 `world_battle_context` 接收交战省地址与双方单位地址数组。和 `resolveBattle` 共用参加者地点校验，返回每个单位所在省的地形及补给，以及从相邻省接触时的路段事实。同省参加者直接显示所在省。GM 在对应剧本时刻提交裁决。

验收覆盖缺图源、过河候选与人工确认、连续铁路路段、铁路停用后的补给变化、行军和交战条件一致，以及旧存档的状态哈希。图源参考和已知事实的版本随导出保留，行军记录冻结出发时使用的条件。
