## 1. 范围

首个可运行样例从 `main-0` 分叉，保存 1936 葡萄牙的剧本归属和有来源的单位部署。地图上可以点选单位所在省及单位标记，通过地址查看理想编制和实际编制，并切回不同的保存节点。用户在 2026-11-19 授权「开始coding！」。该切片使用逻辑坐标和源地名，从草案确定以下接口。全图外部经纬度配准沿用独立调查。

## 2. 地图和单位模块

地图拥有省形、定位和显示所需的地理数据。军事单位模块拥有单位身份、部署、编制关系、理想和实际编制。地图读取同一节点下的派生标记，展示单位地址、所在省地址、名称和显示点。默认显示点取所在省已有的 `displayPoint`，同一省可列出多个单位。单位尚未部署时仍可通过单位地址查询。

部署单位实例代表一张地图兵牌的顶层单位。直属及逐级下属编制使用该实例所引用的 ORBAT 子树表达，团、营、连、排等编制节点的可见列表归属该树。兵牌和叠牌名单只查询部署实例，具体显示见[查看器契约](2026-11-19-readonly-map-viewer.md#兵牌和编制图窗口)。

军事单位地址为 `<branch>-<tick>/orbat/unit/<unitId>`，编制文档及其节点地址为 `<branch>-<tick>/orbat/doc/<documentId>[/node/<nodeId>]`。理想编制可以在文档 ID 后使用 `/version/<contentHash>` 指定不可变内容。两者共用 `NodeAddress`。省份查询可以返回部署在该省的单位地址，点标记后将单位地址交给其领域模块解析。部署调整修改 `provinceId`，单位身份沿用同一 `unitId`。按其他节点访问该单位时，从目标节点读取当时的记录。

## 3. 通用原生格式

沿用既有设计中的 `orbat-native-v1`。理想和实际使用同一种树结构，各自有独立记录。模板可以作为共享的理想编制。单位可分别引用生效的理想编制节点和记录自身实有情况的实际编制节点。实际记录可以在同一军队文档中展开成树，每个部署单位通过稳定的文档与节点 ID 指向自己的实际子树。资料只给出单位名称和地点时，可以先记录部署，两类编制显示为未知。

| 部分 | 建议字段与约束 |
|---|---|
| 文档 | `format` 固定为 `orbat-native-v1`，`documentId` 为稳定 ID，`role` 取 `ideal` 或 `actual`，`root` 为编制根。可附资料日期。 |
| 节点 | `nodeId` 在同一文档内稳定且唯一。主干包括名称、类型、层级、本级直属人员与装备、`children`。已知的增配、缺口和实际下属结构都能表示。 |
| 数量 | 统一使用 `value/status/source/confidence`。数量为非负整数或 `null`。已确认和估计分别标 `known`、`estimated`，都需记录来源。未知用 `unknown`，旧数据语义有歧义用 `legacy-ambiguous`，两者的有效数量为 `null`。置信度缺失保留 `null`。 |
| 装备覆盖 | `equipment` 包含 `coverage` 和 `items`。覆盖取 `complete`、`partial` 或 `unknown`，完整的空表需要来源支持。每条装备记录含目录 ID 或来源名称及通用数量记录。 |
| 行军速度 | 可选的 `marchSpeed` 保存直属行军单位的公里每小时与来源。[计算规则与工具](2026-11-20-unit-movement-duration.md) |
| 扩展 | `extensions` 以模块命名空间为键，值保存对应版本及数据。通用读取和交换保留扩展内容。具体字段的校验、解释和展示交由所属单位模块。 |

以下数量为格式示例。两侧编制均使用下列结构，通过 `role` 声明口径。

```json
{
  "format": "orbat-native-v1",
  "documentId": "example-actual",
  "role": "actual",
  "root": {
    "nodeId": "example-root",
    "name": "演示营",
    "type": "infantry",
    "echelon": "battalion",
    "personnel": {
      "value": null,
      "status": "unknown",
      "source": "fixture:strength-not-reported",
      "confidence": null
    },
    "equipment": {
      "coverage": "unknown",
      "items": []
    },
    "children": [],
    "extensions": {}
  }
}
```

理想编制引用建议包含文档 ID、节点 ID 和编制内容 hash。模板更新后可显式提交启用新版的变更。实际编制用文档和节点 ID 解析到当前保存节点中的记录。共用理想编制的两个单位可各自保有不同的实际记录。编制节点能对应时按统一口径计算差额，缺少对应或数量时保留待核对状态。上级合计由直属数据汇总，查询返回数量与资料覆盖。

## 4. 查询与变更

- 省份和地图标记按已保存节点返回可解析的单位地址。通过单位地址读取单位摘要和理想、实际编制引用，完整编制树按需查询。
- 国家地址为 `<branch>-<tick>/country/<countryId>`。国家数据保存名称、可选别名、首都省、颜色及证据。每省归属与控制分别记录，证据含来源、状态、置信度和可选资料日期。缺失时保持未知。改变控制可独立于归属。显示颜色属于国家资料，外交与战斗规则后续设计。
- `world_search` 根据当前或给定保存节点中的名称、ID 和别名返回分页候选。适用于省、州、战略区域、国家和单位，返回同一套地址与稳定 ID。搜索索引是可重建派生数据。
- 通过 GM 命令 `putCountry`、`setTerritory`、`putOrbatDocument`、`importMilOrg`、`putUnit` 和 `deployUnit` 编辑草稿。归属命令传明确省 ID 列表和要改的字段，预览汇总覆盖与被替换的归属。理想引用在命令规划阶段绑定内容 hash。预览、应用和保存继续走 `Command → ChangeSet → TimelineNode`。
- 已保存节点上的单位、部署省和编制引用在同一状态下校验并回放。每个单位在一个节点有一个有效最终态。具有循环层级或无法解析引用的变更在预览中返回错误。

## 5. 兼容与验收

DSH `mil-org` 作为交换格式。导入通过指定的理想或实际口径落入原生文档。旧数据中的空或零量在语义不明时保留待核对状态，原始数量依据保留在扩展里。兼容导出选择其中一侧，返回 `mil-org` 与损失报告。原生格式保存稳定 ID、来源及扩展，旧地图节点用现有 canonical JSON 和 hash 验证。

快照增加可选 `country` 与 `orbat` 内容分块。旧快照缺少分块时解析为空，空领域从 canonical JSON 省略。理想文档的历史内容随引用保留。单位标记和国家底色由保存状态派生，底图可沿用同一份地理形状、显示点与瓦片资源。

首版验收覆盖名称查 Lisboa、79 省的 1936 葡萄牙归属、同省多个标记与地址跳转、共用理想编制的两个单位保有独立实有、零和未知区分、调整部署后切回历史节点，以及 `mil-org` 往返的兼容报告。
