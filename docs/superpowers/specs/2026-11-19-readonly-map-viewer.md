# 只读地图查看器

> **状态**：有效（首版工程设计）
> **日期**：2026-11-19
> **本文性质**：专题设计
> **目标依据**：[用户原稿 §6.1、§7](2026-11-17-worldsim-architecture-design-source.md)。

用户在恢复核对并听取查看器实施顺序后授权开工，原话为「开始吧」（2026-11-19）。下述协议是首版工程设计。

## 范围与所有权

查看器展示当前世界的已保存地图。可平移缩放、同时点选省份及其所属州和战略区域、按名称、ID 或节点地址定位、切换地形、归属和控制着色、叠加铁路、补给中心与兵牌，以及在已保存节点之间切换。河流随地形底图绘制。编制部署通过单位模块接入。

默认入口仍从工作目录的 `world/` 加载。可单独运行 `viewer [--port 8765]`，也可用 `mcp --viewer-port 8765` 在 GM stdio 进程内同时启动查看器。HTTP 仅绑定 IPv4 回环地址，供 WSL 与 Windows 的浏览器访问 `http://127.0.0.1:8765/`。端口取 0 时由系统分配。启动地址走 stderr。组合模式下，HTTP 和 GM 共用同一个应用服务和世界锁，stdin 关闭即结束会话。

地图和时间线仍拥有权威数据。查看器从应用层取 `NodeRef`、状态 hash 和不可变地图。渲染图、空间索引与传输数据是进程内派生数据，可随进程退出丢弃。浏览器只访问显式的只读端点与随 jar 打包的界面文件。

## 只读接口

| GET 路径 | 参数 | 返回 |
|---|---|---|
| `/api/nodes` | `offset`、`limit` | 已保存节点分页，沿用现有时间线查询 |
| `/api/timeline` | 可选 `branch` | 分支列表、head、从创世到 head 的线性节点和剧本日期 |
| `/api/marches` | `node`、`hash` | 行军路径、进度、部署省和剧本时间 |
| `/api/battles` | `node`、`hash`、`offset`、`limit` | 当前节点可查的交战记录及标记位置 |
| `/api/map` | 可选 `node`，省略时用默认 head | 世界、节点与状态 hash、逻辑坐标范围、地图数据数量、底图比例与瓦片参数、底图版本和本节点战斗兵牌 |
| `/api/overview` | `node`、`hash`、`layer` | 全图 PNG |
| `/api/tile` | `node`、`hash`、`layer`、`level`、`x`、`y` | 指定缩放级别、列及行的 PNG |
| `/api/province` | `node`、`hash`、`address` | 省份资料、稳定 ID、地址、原始选中轮廓和来源提示，以及所属州和战略区的实体资料与合并轮廓 |
| `/api/pick` | `node`、`hash`、`x`、`y`、可选 `layer` | 默认返回与 `/api/province` 相同的组合结果。兼容查询可指定 `state` 或 `region` 仅获取相应区域。空白为无命中 |
| `/api/logistics` | `node`、`hash` | 补给中心显示点和铁路省链示意线 |
| `/api/units` | `node`、`hash` | 部署单位的地址、省份、显示点、兵种、层级及所属国家的显示资料 |
| `/api/entity` | `node`、`hash`、`address` | 实体资料。州和战略区同时返回整区轮廓与显示点 |
| `/api/search` | `node`、`hash`、`query`、可选 `kind`、`offset`、`limit` | 地图实体、国家与单位的名称或 ID 分页候选 |

图层参数取 `terrain`、`state`、`region`、`owner`、`controller` 或 `owner-gaps`。图块由左上原点按行列铺开，坐标向右、向下递增。缩放级别每级像素密度加倍。Java2D 从有洞、可能多部件的省形生成底图和当前视口瓦片。JTS 空间索引先筛候选，再以原始几何判定命中。共享边界按稳定省 ID 排序取首个命中。铁路按省链显示为示意线。容量或距离缺失保持未知。

对带节点和 hash 的请求先查已保存状态，再校验版本。hash 冲突回应 409，畸形参数回应 400，未知节点或实体回应 404。浏览器切换节点时清除旧请求和选中状态，只有当前节点的查询响应可以更新其动态叠层。

## 线性时间线与节点时间

2026-11-20 用户原话

> 此外目前依旧没有实现线性的时间线显示，单个节点似乎没有明确时间标识只有名称，这个应该先修复

浏览器沿分支父链提供线性节点条带、日期、前后步进和跳转。地图随节点显示行军路径，切换同图幅节点时保持视口。时间与行军载荷见[剧本时钟、行军与线性回放](2026-11-20-simulation-clock-and-marches.md)。

交互查询按实际父链从最近经 hash 核对的内存状态或 checkpoint 继续回放。相同的地图分块引用可复用已读取的不可变地图，成功的地图校验和规范 JSON 的地图哈希前缀按该地图身份复用。增量回放逐节点验证原有状态 hash。内存缓存保留有限节点和地图。全量验证从磁盘重新读取已提交数据、复算 hash 并校验几何。

浏览器以底图版本、图层和瓦片坐标复用已解码图片。同一地图跨节点沿用地形底图。政治着色在国家域数据改变时更新，归属调试按节点刷新。地图、全图和瓦片缓存均有限额。

## 州与战略区域点选

2026-11-19 用户原话

> 能不能让州轮廓和战略区轮廓内的填充覆盖在地形格上？类似于钢4，点击一个小格子，自动算作选中这个格子、选中这个格子所属的省份和战略区，而不单独显示省份和战略区

浏览器按原生省形点选地形格，同次响应返回该格及其所属的州、战略区。在同一张地图上，由外至内填充战略区、州和地形格，透明填充保留底图颜色、省界和河道。三者用颜色和实虚线区分。未分组的地形格显示其现有层级。合并几何保留区界、洞和分离的地块，按地图和区域按需生成并缓存。

州和战略区可继续用 `state:<id>`、`region:<id>` 或节点地址搜索。浏览器以区内一个地形格进入同一组合选中态，并按该搜索区域范围定位。组合选择在地形、归属、控制和归属缺项视图中可用。原独立着色保留在只读接口，浏览器的旧州或战略区图层链接进入地形。

## 河流接入方案

2026-11-19 用户原话

> 此外我依旧没有看到河流，河流作为地形的一部分应该直接默认标在图上

先读取已固定版本的 Magna `map/rivers.bmp`。用 `git show HEAD:map/rivers.bmp` 从稀疏检出的 Git 对象读取，再用 Pillow 检查像素索引。文件与省图同为 4096×3072，索引 `0`、`1`、`2` 表示源头、汇入与分流，`3` 到 `11` 记录相对河宽。数据路径和图幅可直接对齐现有省形。[固定版本的河流文件](https://github.com/AzurCrystal/Magna-Europa/blob/d7a57759c188a034c49a0e96aceb1702fa76fc74/map/rivers.bmp) · [河流位图格式](https://hoi4.paradoxwikis.com/Map_modding#Rivers)

本地预检的河流位图 SHA-256 为 `fce85b4945e62d814fb649a4527f63a620ad91f4241c0dafcea32fbeee49a3c6`。有效索引共 135,533 像素。用现有 WGS84 参考投影科隆（`6.964,50.941`）、奥得河畔法兰克福（`14.556,52.348`）、华沙（`21.033,52.239`）、布达佩斯（`19.045,47.505`）河边坐标，四处的最近河流像素中心都在 1 个地图单位内。该检查用于确认图幅对齐。

从像素中心按四邻接提取河道折线，在分支处保留连接关系与宽度级。图形和源文件的提交及 hash 作为可选的 `rivers` 字段写入世界的 `geo-reference.json`，沿用外部参考的基准节点、图幅验证及导出流程。查看器在全图和所有着色的瓦片中于省界上绘制河道，随缩放调整显示线宽，组合选中的透明填充叠在其上。现有省形、跨河邻接和时间线的事实仍由领域数据提供。河名与跨河邻接的后续复核需使用独立证据。[地图领域契约](2026-11-17-map-orbat-info-timeline-design.md#24-空间邻接与补给)

1936 剧本准备时从固定图源生成河流。已有配准文件可直接增补后随世界加载。[剧本准备工具](../../../tools/prepare-1936-pilot.py) · [河流参考工具](../../../tools/river_reference.py)

## 兵牌和编制图窗口

兵牌通常为 50×32 CSS 像素。以「全图」为 1 倍，地图可继续缩小至 0.8 倍。低于 0.9 倍时隐藏地图兵牌和点击热区，界面提示放大后显示。0.9 倍至不足 3.5 倍时聚合视口内彼此相邻的部署点并显示单位数，3.5 倍及以上优先给每个单位分配独立兵牌。视口尺寸变化保留相对于全图的倍率。

叠牌的单位数只计已部署的顶层单位实例。一个顶层单位所引用的编制树内，可逐级展示其下属单位。同点或相邻的兵牌允许有限显示偏移，连线指向实际部署点。局部空间用尽时，可从叠牌的完整名单点选。单位地址及部署省取自 [ORBAT 契约](2026-11-19-unit-address-and-orbat-format.md)。

选中单张兵牌或叠牌打开左侧军队面板。叠牌名单支持定位展开与选择单个单位，选中单位提供定位、来源、直属差额及「查看编制图」。直接查询 ORBAT 文档或编制节点的地址时打开编制图窗口。

浏览器内独立窗口用兵牌卡片和连线呈现编制树。上级单位在上，同级下属横向布置。窗口内可切换实际与理想编制、缩放画布、折叠分支、点选任意节点查看直属人员和装备及其证据。关闭窗口回到当前地图选中态。单位军种、编制、数量与来源缺失时保留未知。[Army Editor 结构画布](https://xgua126.github.io/Army_Editor/army-editor/index.html)

### 战斗兵牌

2026-11-20 用户原话

> 首先，在某节点某地发生的战斗应当有一个和兵排在同一界面显示的虚拟“单位”，用于表示这里发生了一场战斗；其次，最重要的，为什么切换时间线这么慢？有没有优化方案？

战斗兵牌是查看器从当前节点的战斗裁决投影出的事件标记，锚点为交战省，地址指向原战斗记录。它与顶层单位共用叠牌、展开、隐藏和点击热区。混合叠牌分别标出部队数与战斗数，名单可分别点开单位详情和战斗裁决。放大时优先为战斗分配独立兵牌。战斗兵牌显示在记录战斗结果的节点，后续节点仍可从战斗列表或地址查阅可见的历史战斗。

## 验收

- 从实际 jar 启动独立查看模式和组合模式。组合模式可通过 MCP 保存新节点，在查看器更新列表后访问新节点及历史节点。
- 在 Magna 实际地图上浏览全图，平移、缩放、点选、按地址定位，查看地形、归属、控制、铁路和补给中心。验证选中地形格时同步描绘州和战略区，以及全图和放大瓦片默认绘制河道。核对莱茵河、奥得河、维斯瓦河和多瑙河四个已配准河边点。
- 核对省的飞地、内环、共享边界、节点/hash 隔离和未保存修改不可见。窗口缩放和键盘可操作基本浏览。
- 在同一部署点保存两个同级且各有下属编制的装甲师。验证放大显示两张师级兵牌，缩小时合为计数 2，最低倍率隐藏。逐一打开两师的编制图，沿连线核对团、营、连、排。
- 验证全图叠牌计数、单独点选、面板与省份查看并行、编制切换与排级层级、清除选择，以及紧凑窗口布局。
- 记录 WSL 本地与 Windows 宿主机的连通性实测，以及来源提示仍待独立复核的事项。
