## 1. 用户原话（逐字，2026-11-17）

> 不用，你可以进一步调查参考一下隔壁SimulatorMosire（把文档规范抄过来），SimulatorMosire项目使用非常细化的六边形地图，这给开发带来了极大困扰，我决定直接把开源的HOI4类似地图给抄过来（省份、格子、补给中心规范等），然后结合ProjectMosire的agentlib库，封装一套mcp工具给Agent方便地编辑、导出，是的，我们还要做一个Simos风格的时间线管理；然后决策人和军队，看见dsh已有的编制协作功能了吗？我们不用HOI4的狗屎军事系统，我们实现INFO+编制编辑器格式与HOI4风格地图结合，这可行吗？

## 2. 目标解释（不改写用户原意）

用户要求的目标可以拆成六件事：

1. **换地图范式**：不再使用 SimulatorMosire 的细化六边形地图；改用 HOI4 风格的不规则省份地图。  
   “格子”在这里指地图的最小空间单元（province cell），不是必须继续使用 hex 网格。

2. **抄规范，不是抄资产**：参考开源 HOI4-like 地图的**省份、格子、补给中心等规范**；不把 vanilla HOI4 资产或来路不明的地图内容直接塞进仓库。

3. **接 AgentLib**：基于 ProjectMosire 的 `AgentLibMosire` 封装 MCP 工具，让 Agent 能编辑、查询、导出世界。

4. **时间线**：实现 Simos 风格的时间线管理——分支 + tick、节点地址、增量状态、检查点、回放。

5. **不采用 HOI4 军事系统**：不移植 HOI4 的 division template、combat width、装备原型和战斗公式。

6. **INFO + ORBAT + 地图结合**：用 INFO（决策人感知/信息层）和 DSH 已有编制协作格式（ORBAT），表达决策人、军队编制和地图态势；ORBAT 负责“组织/人员/装备”，地图负责“位置/地形/补给”，INFO 负责“谁知道什么”。

## 3. 用户目标中的硬约束

1. **地图不再以 hex 为唯一原子单元**。  
   新地图必须有省（province）这样的不规则空间单元；是否还保留 hex 仅作为编辑辅助，不是首版必需。

2. **编制编辑器格式必须保留可交换性**。  
   DSH ORBAT 工作台/`mil-org` 是现成格式；新系统要能导入/导出，并明确损失报告，不得声称兼容格式无损。

3. **INFO 不是自然语言正文仓库**。  
   INFO 记录结构化感知/决策信息；长篇战报、说明、历史叙述走文档系统。

4. **时间线不是按模块各做一套**。  
   地图、编制、INFO 的变更必须能落到同一个 `(branch, tick)` 节点和同一个 ChangeSet 体系。

5. **Agent 工具不是直接改文件**。  
   Agent 只能调用有 schema、有权限、有预览、有提交语义的 MCP 工具；不能直接写 BMP/CSV/ORBAT JSON。

6. **不伪造事实**。  
   编制人数、装备、资源、战斗结果必须带证据状态或生成标注；0/空不等于真实为零。

## 4. 非目标（本阶段）

- 不实现完整 HOI4 政治/经济/军事模拟。
- 不实现 HOI4 mod 的完整运行时兼容或所有 DLC 内容。
- 不把 Mappa Mundi、Blank Map、MapGen、vanilla HOI4 文件直接作为开放资产分发。
- 不在首版做多 Agent 自由外交/全球战争模拟；先做可回放的单世界编辑与编制/INFO/地图闭环。
- 不在本文中裁定工程细节（地图栅格 vs 矢量、同 tick 多写、历史节点编辑等）；这些在专题设计中列为待定项。

### 6.1 第二轮裁定的解释

1. **HOI4 导出不是目标**：不再设计、承诺或排期“导出可加载 HOI4 mod”。HOI4-like 仅指地图/空间/补给规范，不是 HOI4 兼容层。
2. **先做时间线储存 + 静态状态**：首版实现重点是持久化、快照/增量、working copy、save/discard、静态 polygon 地图；ORBAT/INFO/MCP 是后续层。
3. **原生 polygon**：`ProvinceShape` 的 polygon 是权威几何；渲染器可以不画 polygon，只用 province/其他标识符定位显示坐标、选中轮廓。
4. **地址沿用 Simos 并严格**：`treeXXX-tickXXX[/<type>[/<id>...]]`；语法、路径段、branch/tick 都要严格校验。
5. **同节点合并 + 保存闸**：
   - 多次写入按顺序 append 到同一 working ChangeSet；
   - 不做撤销；
   - `discard` 丢弃内存更改，回到快照；
   - `save` 才产生已保存节点；
   - 只有已保存节点能创建下一节点或 fork。
6. **先只能 fork**：不提供原地改写历史节点/自动 rebase；历史分叉只能新建分支。
7. **ORBAT 单节点单单位最终态**：一个单位在一个节点只能暴露一个 effective final state；中间 change/history 可以由实现内部记录，但不能产生两个可见最终状态。
8. **INFO 可承载文本和自定义类型**：短文本、长文本、自定义 typed payload、任意地址、多包/扩展格式都必须支持。此前“长文本一律只进 Docs”的工程建议被本裁定取代。
9. **当前只上 GM**：DM/决策人权限模型暂缓；GM 原则上有完整权限。DM 相关设计保留但不实现。
10. **人类客户端主要用于查看**：不是完整编辑器；复杂编辑由 Agent 做。

## 8. 社区地图补裁（逐字，2026-11-17）

> 我的要求不是直接照搬HOI4的社区地图吗
>
> 你不能自己去下载一个吗，非要从本机找？

解释：

- 用户要求的是**实际社区地图数据**，不是只生成规则矩形 `SyntheticWorld`；后者只是规模测试 fixture。
- 数据源应可由 Agent/开发环境自行下载，不能依赖用户本机 Steam HOI4 安装。
- 首个候选源选用 Mappa Mundi GitHub 版（固定提交），但 raw 资产有许可不确定性，因此 raw 数据放 gitignored `runtime/imports/**`，仓库只提交下载脚本/导入器/测试 fixture。
- “不导出 HOI4 mod”仍然有效；导入社区地图不等于恢复 HOI4 导出。
