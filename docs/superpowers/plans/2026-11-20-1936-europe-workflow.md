## 1. 先交付剧本时钟和线性时间线

此阶段由[剧本时钟、行军与线性回放](../specs/2026-11-20-simulation-clock-and-marches.md)实施。验收快照见[当前状态](../../agents/STATUS.md)。

事件时间线已接入 GM 的预览与保存路径，按相邻路段抵达时刻建立可回放节点。[事件节点契约](../specs/2026-11-20-event-timeline.md)

- **显示**。选定分支后，沿该分支 head 的父链从源头到现在显示节点条带。分叉可换支，每个节点可回看前后一步或直接跳转。节点以剧本日期为主，节点地址和 tick 可查。拖动或切换节点后，地图、军队和前后节点摘要使用同一个节点地址。
- **日期语义**。新提交的剧本时钟使用 ISO 日期时间，精度到秒。准备与补录可沿用同一时刻。两个旧德波导入节点由清单校对为 1936-01-01。`main-0` 是日期未知的地图底板。时间轴按父链排序，同一时刻可有多个不同 tick。
- **实现入口**。复用 `pathToRoot` 和现有节点摘要，给浏览器和 MCP 提供同一条分支序列。先落持久契约，再为新节点保存剧本日期及其出处。导入器从清单传递日期，已保存的德波节点用绑定其地址和状态 hash 的导入证据补齐显示。旧存档可继续读取，缺少日期的节点显示未知。日期随新节点原子提交，保存重试回执包含一致的日期。[现有保存路径](../../../src/main/java/io/mosire/worldsim/app/WorldApplicationService.java#L431)
- **验收**。实际地图上看到 `main-0 → de-pl-1936-1 → de-pl-1936-2`。两次补录显示同一日期。另用独立分支推进一个显式后续日期，检查分叉、旧节点、重新打开存档和重试保存。

## 2. 将史料核对封装成 Skill，按国家并行

仓库 Skill 已落地。德波独立副本的工具链与合并结果见[DSH 试跑](../reports/2026-11-20-dsh-1936-pilot.md)。

用德波试点提炼仓库内的 `.agents/skills/worldsim-1936-research/SKILL.md`。Skill 给出任务包格式、检索与读表方法、证据冲突的处理、MCP 调用顺序、回执交付示例。用已核对的省与师部做一次端到端试跑，再派法国、捷克斯洛伐克、意大利三个 DSH 任务。已确认本机 `dsh headless --help` 支持独立任务和权限预设。实际 Skill 加载与副本 MCP 联通在试跑中验证。

1. **统一输入**。每项任务收到同一个 1936-01-01 已保存节点、状态 hash、固定图源提交、国家 ID 和待核对范围。由 `world_export` 取得共同输入，每个任务使用独立工作目录和世界副本。工作区权限和 MCP 运行目录限定到各自任务。
2. **版图**。从同日历史边界提取候选省，在当前底图上用 `world_geo_lookup`、`world_search` 和 `world_lookup` 确认省地址。对照州史、普通陆地邻接和地方史复核偏差、飞地、跨境争议及来源不一致处。归属、实际控制分别记。对照当前范围的缺项报告、邻接和地图截图。
3. **军队**。核对开局日的常备师序列、番号和师部驻地，再向下录有据的编制。编制树用 `orbat-native-v1`，驻地与实编、理想编制各有其证据。史料只给编制时保留实有人数和装备为未知。记录资料页、原文地名、地图地址、日期、证据状态和置信度。
4. **副本验证**。每个任务交付现有格式的 `scenario.json`、带检索词及来源页码的查证记录、预览与保存回执、边界与部署差异、待复核项。用 `putCountry`、`setTerritory`、`putOrbatDocument` 和部署命令，经 `edit_apply` 预览和应用。副本保存后核查缺项、师级分布和编制。
5. **统一落库**。GM 对比各任务包修改的省、归属字段、国家及单位 ID。跨国争议和重复命令在汇总时裁定，重新在共同目标节点预览，确认实际基点后统一保存。后续批次可依同一流程做英国、奥地利、苏联欧洲部分及其他国家。[德波实测路径](../reports/2026-11-19-1936-source-research.md#导入和验证方法) · [现有导入器](../../../tools/submit-scenario.py)

## 3. 用德波样本打通行军与单场战斗

速度估算、逐段部署更新和保存节点上的路线回看已接入同一流程。[行军速度与耗时](../specs/2026-11-20-unit-movement-duration.md) · [实际行军工具](../specs/2026-11-20-simulation-clock-and-marches.md)

行军和交战预览共用跨河与铁路条件。已确认的闭线影响铁路补给连通。[地图条件](../specs/2026-11-20-land-edge-conditions.md)

- **行军工具**。以单位地址和陆地省链建立行军，按分钟推进并在抵达时更新部署。新行军查询各段通行、地形和补给。推进时复核进入地块的许可。首版补给依据铁路与补给中心可达性。
- **单场战斗**。GM 提交结构化结果、损耗及可选控制变化。程序核对基准状态，写入实际编制与战斗记录。后续可按实际推演需要扩展接触、战斗规则及补给消耗。[战斗与行军规则](../specs/2026-11-20-battle-and-march-conditions.md)

## 5. 验收 GM 管理的双国回合

阶段 2 的史料任务可与国家领域开发并行。用德波已录的开局完成一个含政治、经济与外交读写的和平回合，再用独立演练分支验收决策提交如何进入现有行军和战斗裁决。

两个决策人读同一节点下 GM 授予的视图并分别提交决策。GM 汇总两国输入、保存结构化裁决及下一个时间线节点。MCP 可追溯简报、决定和结果，浏览器可在相邻节点核对时间、军队和领土。DSH 史料任务和游戏决策人分别使用各自会话、数据范围和工具权限。
