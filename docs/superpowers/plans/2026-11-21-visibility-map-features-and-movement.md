## 实施顺序

1. **确定可见性与指挥身份。** 国家保留完整的核心档案；对外文档可投给全部、指定国家或指定组。DocsMosire 管正文和挂载，节点保留发布版本和受众。总参谋部、集团军参谋部各有稳定地址，可以挂决策人和机关库存，并保存指挥关系。GM 授权决定档案、所属单位、运输和情报可见范围；地图、搜索、右栏与 MCP 采用同一服务端判定。
2. **接上三种独立地图标记。** 港口和资源点各有稳定 ID、所属陆省和证据，由地图域维护位置。港口可记录已核对的相邻水域和通航状态，容量按有据口径录入。资源点记录种类及位置；有来源时再记产量、单位、时间和开采状态。只有州级资料时，保留州级统计和定位待办。情报标记由 INFO 管理，身份、受众和疑似对象分别保存，GM 创建的标记归属 GM。右栏和地图图层分别显示可见的标记。
3. **完成陆路调动的回合流程。** 给决策提案增加结构化调动意图，含单位、终点、可选途经点。决策者按当前可见信息判断路线；GM 可用真值环境预览合法路径、时间及阻塞原因，通过现有行军命令发布和推进。GM 工具增加按终点生成候选路线的入口，同时接收显式省链。试点补齐少量实编速度和关键路段配准，对缺速度、缺距离、无通行权给可执行的诊断。界面显示批准、进行中、暂停或受阻、已抵达或取消，并按已获授权信息显示路线。
4. **扩展铁路转运与港到港运输。** 用独立运输方式描述铁路和海运分段。铁路转运接当期运力及共同路段约束，需要先确定人员、装备和运力的换算口径。海运第一版限定可用港口之间的运输，记录登船、航行、卸载和抵达；可用泊位、运输能力、通行条件够用时才批准。港口两端、海上分段及陆路接续沿用同一时钟和节点回放。资源产出、海军作战和登陆另按后续需求设计。

港口和资源点的史料清单可与第一步并行准备。新数据和权限进入持久状态前另定专题契约。所有发布、撤回、转运与行军通过 AgentLib 工具和 `Command → ChangeSet → TimelineNode`。旧存档按缺少新增字段读取，保持其节点哈希。情报标记的候选位置只供决策判断，真值路线、运力扣账及战斗输入按实际地块和实体结算。

## 联合验收

- 在独立 1936 分支录入两个可定位的港口和至少一个有省级证据的资源点。另取一条只有州总量的资源记录，核对州级资料可查且各省显示待定位。
- 用国家、总参、一个集团军参谋部、两个下属单位和一个对方观察者测试。GM 定向发送一条标记，一个单位上报后由上级定向分发；核对接收端只能读授权文档和标记。核对搜索、地图计数、兵牌与路线同时过滤，撤回后可回看旧节点。
- 让实编速度具备依据的一支部队提交陆路调动，GM 预览并发布，推进到两次路段事件。用同一时间线回看原意图、裁决、途中状态和实际抵达。以受阻路线、未配准路段与未知速度验证失败原因。
- 陆路闭环通过后，分别演练一次铁路转运和一次港到港运输，核对容量占用、取消或港口关闭时的处理、重复提交与回放。
