## 配置与输入

使用 DSH 0.2.2-rc.3。将 [worldsim-1936-research](../../../.agents/skills/worldsim-1936-research/SKILL.md) 放在各副本的 `.agents/skills`。两份任务均以 `de-pl-1936-1` 及同一基点哈希为准。德国用 Königsberg 省 19906 和第 1 步兵师师部，波兰用底图拼写 Sieldce 的 19914 和第 9 步兵师师部。每份采用已查证的三条命令，分别写省归属、实编和部署。来源省份、查证路径与编制依据见[德波回填记录](2026-11-19-1936-source-research.md#德波开局复核与补录)。

生成每个任务的本地 overlay，启动命令与工作目录由分配方指定。工作目录内含独立的 `world/`。

```yaml
- insert:
    - id: worldsim-pilot
      name: '@deepseek-ai/dsh-mcp-client'
      config:
        serverName: worldsim
        transport: stdio
        command: java
        args: ["-Xmx3g", "-jar", "/absolute/path/to/worldsim.jar", "mcp"]
        cwd: "/absolute/path/to/task-copy"
```

在任务目录运行 `dsh headless --patch ./dsh.patch.yml --json --permission-mode workspace-write --approval-policy never - < task.txt`。清单和原始资料均可随任务提供。核对结果时读 DSH 的工具调用与回执，而不是只读最后消息。

## 验证记录

- skill-creator 的 `quick_validate.py .agents/skills/worldsim-1936-research` 返回 rc=0。
- 两次在线 DSH 启动了 Java MCP，模型调用返回 `MISSING_CREDENTIAL`。在线模型自主查证与法国、捷克斯洛伐克、意大利的实际任务验收为 `NOT_RUN`。当时日志在 `target/civic-dsh-pilot/{GER,POL}/dsh.stderr`。
- 以回环地址上的固定模型响应驱动 DSH，两个进程均 rc=0。DSH 实际加载 Skill、核对基点和省地址、建分支、预览、应用、保存并回查师部。两次预览与应用哈希相同。德方回执节点 `dsh-ger-2`，波方回执节点 `dsh-pol-2`。输入、调用记录和结果位于 `target/civic-dsh-pilot/{GER,POL}/`。本地试验验证工具链，在线模型自主判断待单独验收。
