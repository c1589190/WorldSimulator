# docs/AGENTS.md —— 文档系统规则（项目维护）

> **本文件属于项目维护，不属于项目设计。**
> **用户原话（2026-11-17，逐字）**：
>
> 「你可以进一步调查参考一下隔壁SimulatorMosire（把文档规范抄过来）」
>
> **当前状态入口**：[`docs/agents/STATUS.md`](agents/STATUS.md)。本文件只规定“文档放哪、谁说了算、什么时候写、怎么被检查”。

## 一、两条文档轴：项目设计 ≠ 项目维护

| 轴 | 收什么 | 正本位置 | 不放在哪里 |
|---|---|---|---|
| **项目设计** | 地图/省份/州/补给规范、ORBAT/INFO 语义、时间线状态机、模块边界、工具面/载荷、跨模块数据所有权、领域公式 | `docs/superpowers/specs/**`；最高权威是用户设计原稿 `docs/superpowers/specs/2026-11-17-worldsim-architecture-design-source.md`；索引在 `docs/superpowers/DESIGN_RULINGS.md` | 不写进 `docs/agents/MAINTENANCE_RULINGS.md`；不把维护流程塞进设计原稿 |
| **项目维护** | 文档系统、门禁/验证、工作流、子 Agent 协作、工作树/环境、提交/归档/检查脚本 | `docs/agents/MAINTENANCE_RULINGS.md`、`docs/AGENTS.md`、`docs/agents/STATUS.md` | 不写进设计原稿；不冒充用户设计裁定 |

**分账规则**：

1. 一条规则只能有一个**主正本**；另一侧需要提及时只放链接，不复制全文。
2. 同一条用户原话同时影响两边 ⇒ 拆成两行：设计影响写入设计文档，维护影响写入维护裁定；两边各自给原话出处。
3. 代码行为“为什么这样”属于设计；代码怎么被验证/派单/提交属于维护。
4. 分不清时先停手，按用户原话补充分类；不得默认塞进 `AGENTS.md` 或旧长文。

## 二、文档分层

| 层 | 路径 | 放什么 | 何时加载 |
|---|---|---|---|
| 常驻路由 | `AGENTS.md` | 项目简介、冲突顺序、常驻红线、文档/模块索引 | 总是 |
| 目录局部 | `docs/AGENTS.md`、`docs/superpowers/AGENTS.md`、`docs/agents/AGENTS.md`（若建立）、各模块 `AGENTS.md` | 本目录特有规则和局部索引 | 触达该目录后按祖先链加载 |
| 实时状态 | `docs/agents/STATUS.md` | 当前目标、源码基线、最近验证、未验证项、下一步 | 每次开工/收工、上下文压缩前 |
| 维护裁定 | `docs/agents/MAINTENANCE_RULINGS.md` | 文档、门禁、协作、环境等维护裁定的**逐字原话 + 落点** | 需要改维护机制前 |
| 用户设计原稿 | `docs/superpowers/specs/2026-11-17-worldsim-architecture-design-source.md` | 用户当次目标的逐字原话、解释、范围 | 设计/实现前必读 |
| 专题设计 | `docs/superpowers/specs/**` | 地图、ORBAT、INFO、时间线、MCP 工具面、导出、不变量 | 设计/实现前 |
| 调查/评审 | `docs/superpowers/reports/**`、`reviews/**` | 邻仓侦察、技术可行性、证据、独立复核 | 评审/溯源 |
| 计划 | `docs/superpowers/plans/**` | 进行中的实现计划；完成后归档/转决策记录 | 派单/执行前 |
| 历史快照 | `docs/superpowers/status/**` | 某时点状态、交接、证据摘要；**不是当前状态入口** | 追溯历史时 |
| 历史调研 | `docs/hoi4-community-map-resources-survey.md` 等 | 上一轮公开生态调研；只作输入 | 需要背景时 |
| 机械强制 | `tools/check-docs.py` | 能退出码判定的检查：必需文件、状态头、相对链接 | 直接运行 |

## 三、权威顺序与取代关系

### 3.1 冲突顺序

1. 用户当次明确指令；
2. 项目设计裁定（用户设计原稿 / 当前有效设计）；
3. 项目维护裁定（`MAINTENANCE_RULINGS.md` / 本文件）；
4. 当前有效专题设计或契约；
5. 根 `AGENTS.md` 的常驻路由；
6. `STATUS.md` 中的当前事实（只覆盖事实，不覆盖设计/维护规则）；
7. 旧长文、历史 status、归档文档。

### 3.2 取代怎么写

- 被取代的文档**不删**，在文件头加：
  `> **状态**：历史（YYYY-MM-DD）· **取代者**：<路径> · **勿据此开工**。`
- 取代者一侧在标题下写：
  `> **本文取代**：<旧路径>（YYYY-MM-DD）。`
- 局部修正只标范围和取代者，不把整篇历史文档改写成“当前事实”。
- **不得按文件名日期推断有效期**；以正文状态头、用户原话日期和实际代码/测试为准。
- 调研文档如果只是输入、不是设计正本，标 `状态：调研输入`，不要让后来者当契约实现。

## 四、记录频率

| 触发 | 必须记录 |
|---|---|
| 用户给出新裁定 | 先分类：项目设计还是项目维护；设计写设计原稿/专题 spec，维护写 `MAINTENANCE_RULINGS.md`；都保留原话和日期 |
| 开始一个责任区 | 在 `STATUS.md` 写当前目标、范围、预期产物；计划落 `docs/superpowers/plans/` |
| 完成一个可验证步骤 | 更新 `STATUS.md`：改动、命令、rc、测试数、证据路径、未验证项 |
| 发现文档矛盾 | 记录双方路径/日期/事实；能判定的在旧文加取代头；不能判定的列入待裁定 |
| 子 Agent 交接或上下文压缩前 | 更新 `STATUS.md` 的下一步第一条命令、当前 dirty、未验证项，写清可继续工作的最小上下文 |
| 变更维护机制 | 先写 `MAINTENANCE_RULINGS.md` 条目，再改脚本/CI/目录；脚本是执行面，不是第二份正文 |

**当前状态唯一入口**：`docs/agents/STATUS.md`。任何 dated status 文件都只是历史快照。

## 五、STATUS 模板

`docs/agents/STATUS.md` 至少包含：

```text
更新时间（绝对日期 + 时区）
当前目标 / 进行中范围
源码基线（分支、HEAD、工作树状态；尚无代码时写“无代码”）
最近验证（命令、rc、测试数、证据路径、是否 full）
当前有效设计/维护入口
未验证 / 风险 / blocker
下一步（可执行的第一条命令）
```

## 六、目录级 AGENTS 规则

- 每个有独立工作规则的目录可以有 `AGENTS.md`；根到 cwd 的每一级会被 harness 按祖先链加载。
- 局部文件必须短，写：本目录职责、局部边界、关键入口、验证命令、当前文档入口。
- 局部文件**不得复制**根红线、不得另立用户裁定、不得把历史状态写成当前事实。
- 局部规则只在本目录范围生效；与项目设计/维护正本冲突 ⇒ 停手上报。

## 七、Skill 与规则的边界

| 规则形态 | 去处 |
|---|---|
| 项目设计硬约束（模块边界、数据所有权、地图/ORBAT/INFO/时间线语义） | 设计原稿 / 专题 spec |
| 项目维护硬约束（文档格式、门禁、提交、工作树） | `MAINTENANCE_RULINGS.md` / 本文件 |
| 能机械判定的内容 | `tools/check-docs.py` / 测试 |
| 只在某类重复任务里使用的判断流程 | 宿主可发现的 Skill（本仓暂不批量造空 Skill） |
| 当前事实和一次性证据 | `STATUS.md` / `docs/superpowers/status` / 报告 |

## 八、引用与日期

- 引用用户原话必须**逐字**，日期取用户实际说出的日期；不是文件名日期，也不是提交日期。
- 现状事实要给 `file:line`（邻仓证据用 `~/仓库/路径:行`）；跑过的结论要给命令、rc、关键输出与证据路径。
- 没有跑过的，不写“通过”；只写 `NOT_RUN` / `未验证` / `BLOCKED`。
- 历史事实与当前事实分开；历史文档不回头篡改，只加状态/取代头。
- 长文一律用普通 Markdown 链接，不用 `@` 导入。
